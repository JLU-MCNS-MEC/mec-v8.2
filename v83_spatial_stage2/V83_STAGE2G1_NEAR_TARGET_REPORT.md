## 1. Data supplement

### 1.1 Matched near-visible / near-invisible pairs

`stage2g1_supplement.py` samples, for each pair:

- one existing Train 600 or Dev Val 180 episode (same goal, scene, seed);
- one position at true distance 5–100 m from the goal;
- four frames `t-3 … t` generated by the same three actions for both variants:
  - **near-visible:** goal relative angle `-25° → +20°`; target visible in all
    four frames;
  - **near-invisible:** goal relative angle `+20° → +65°`; target visible at
    `t-3/t-2`, invisible at `t` (the target leaves the 90° FOV).
- The near-visible and near-invisible states therefore share episode, position,
  distance, goal tokens and the **identical RIGHT ×3 action sequence**; only
  the initial yaw and visual history differ. This is the paired control that
  prevents action/distance/scene shortcuts.

Counts and cost:

| Split | Pairs | States | Near-visible localizable | Near-invisible | Size | Time |
|---|---:|---:|---:|---:|---:|---:|
| Train 600 | 1,600 | 3,200 | 1,596 / 1,600 | 1,600 | 1.47 GB | 126 s |
| Dev Val 180 | 400 | 800 | 400 / 400 | 400 | 0.37 GB | 33 s |
| **Total** | **2,000** | **4,000** | **1,996 / 2,000** | **2,000** | **~1.84 GB** | **159 s** |

Distance quantiles (Train / Dev Val): median 40.3 / 40.2 m; 10–90% 13.1–84.9 /
13.7–83.9 m. Encoder: `runs/archive_pycharm_v82_20261018/shared_encoder.pt`,
sha256 `8ee6194e83ea6c6845f22d0ad271066fb82401d781906da9d4c624ab0a556f56`
(frozen; no M0/M1 forward, no checkpoint modification).

Per state the supplement saves current RGB tokens (576×384), goal tokens
(3×384), heatmap (3×8×8), baseline/coherent maps (24×24), the 2,858 current
features, three previous-frame compact features (74 each), actions, dt,
pair/variant/episode/step IDs and the labels. True distance/visibility/
projection are separate label arrays and never model inputs.

### 1.2 Hard-state short history (synthetic, documented)

The isolated hard arrival/distractor samples have no logged trajectory. Using
them with a missing-history flag would let P1 use "history missing" as a
shortcut. `stage2g1_hard_history.py` reconstructs each hard pose with the same
RNG stream and renders a real three-step RIGHT-turn history ending at the exact
pose (`t-3 = final yaw +45°`, `t-2 = +30°`, `t-1 = +15°`, `t = final`). Only
compact observable features/actions/dt are saved.

| Split | Hard states | Size | Time |
|---|---:|---:|---:|
| Train 600 | 3,600 | 3.3 MB | 96 s |
| Dev Val 180 | 1,080 | 1.0 MB | 28 s |

This history is synthetic in the sense that the original hard sample was a
single isolated pose; it is used only for P1, and it removes the missingness
flag. Natural states use their actual previous frames (50,165 Train / 15,614
Dev Val); the first three frames of each natural episode (1,800 / 540) have no
usable history and are excluded from the P0/P1 common comparison.

### 1.4 Labels and leakage

Labels use the existing Stage-2g definitions:

```
target_visible     = occlusion-aware visible_pixels >= 1
target_localizable = target_visible AND goal_half_size_px >= 10
                     AND visible_pixels >= 16
near_target_invisible = true distance < 100 m AND target_visible == 0
```

`near_target_invisible` is a **diagnostic target only**; it is never a model
input. The current features, compact history features, actions and dt contain
no true distance, visibility, heading, goal coordinate or oracle action.
P0 uses only the 2,858 current features; P1 uses current plus previous-frame
compact features/actions/dt. The 74 compact history features and the 768
goal-only baseline features are checked for forbidden terms by tests.

## 2. Probe design

- **P0:** current 2,858 observable features.
- **P1-k:** current + k previous frames, k=1,2,3. Each frame contributes 74
  compact visual features + 4-way action one-hot + dt = 79 dimensions.
  P1-1/P1-2/P1-3 inputs are 2,937 / 3,016 / 3,095 dimensions.
- MLP: one hidden layer of 128 units, ReLU, dropout 0.2; 30 epochs; Adam
  (lr 1e-3, weight decay 1e-4); batch 8,192.
- Class-weighted BCE; the class prior is undone by the exact prior-correction
  formula before Brier/ECE/confusion. Weights: near-inv ~33.6, visible ~0.046,
  localizable ~0.38 on Train.
- **5-fold episode-level OOF on Train 600** (no adjacent frame crosses folds)
  and **external validation on Dev Val 180** (independent episodes). The
  trigger threshold is selected on Train OOF only; Dev Val is held out.
- Three heads: `target_visible`, `target_localizable`, and the diagnostic
  `near_target_invisible`.

### 3.7 Controls: scene, distance and hard-state history

| Control | Result |
|---|---|
| Paired near-visible vs near-invisible AUC (same episode/position/distance, identical actions) | P1-2 near-inv **0.990**; visible 0.988; localizable 0.972 |
| Goal-only baseline (768 goal-token features) | near-inv AUROC **0.522**; near-vs-far-inv AUC **0.495**; paired AUC **0.500** |
| Distance-only diagnostic (true distance, offline only) | near-vs-far-inv AUC **1.000**; paired AUC **0.500** (same distance within a pair); not a model input |
| Near-inv vs hard far-invisible AUC | P1-2 **0.947**; P1-3 **0.954** |
| Near-inv vs natural far-invisible AUC | P1-2 **0.969**; P1-3 **0.965** |
| Common valid-history data scale | Train 58,765; Dev Val 18,034; 600 / 180 episodes |

The paired AUC is the key anti-shortcut control: within a pair the episode,
position, distance and actions are identical, so a 0.99 AUC must come from the
current/history visual evidence. The goal-only baseline is chance on both the
near-vs-far and paired comparisons; the distance-only diagnostic is perfect on
near-vs-far by construction but exactly 0.5 within pairs. The near-vs-far gain

## 4. Error analysis

1. **Current-only is insufficient.** P0 near-inv AUROC 0.848 but trigger
   precision 0.204 and far-visible FT 6.3%; the near-vs-far-invisible AUC is
   only 0.702. The current frame can see that a target is absent, but it cannot
   tell a near target that just left the FOV from a far target that was never
   localizable.
2. **One history frame is borderline.** P1-1 raises near-vs-far to 0.827 and
   paired AUC to 0.946, but the f1 point precision is 0.481 (CI lower 0.424),
   below the 0.50 gate. Its recall-0.5 precision is 0.517 (CI lower 0.454).
   Single-frame history is not robust enough.
3. **Two frames are the main gain.** P1-2 near-vs-far 0.951, paired 0.990,
   trigger precision 0.914 (CI lower 0.882), far-visible FT 0.07%, recall
   0.813. The history is long enough to encode "the target was recently
   visible and the agent turned away" versus "no recent localizable target".
4. **Three frames add little.** P1-3 improves precision by ~2 pp and recall by
   ~2 pp over P1-2; near-vs-far +0.005. The extra frame is not necessary for the
   offline gate.
5. **The localizability probe fails.** Even with two/three frames, its
   near-vs-far AUC is 0.615/0.637 and trigger precision 0.314/0.365. The
   localizability label is largely a target-size/distance label; short history
   does not turn it into a near-loss detector. Do not use it for the gate.
6. **The visibility probe passes nominally but is unsafe.** P1-2/P1-3 precision
   0.615/0.631 and far-visible FT 0.43%/0.40%, but far-invisible FT is
   45.7%/43.6%. Stage-2f showed that firing at far states is harmful, so the
   visibility probe is not the safe candidate despite the written gate.
7. **The diagnostic near-inv head is the clean candidate.** P1-2/P1-3 precision
   0.914/0.935, far-visible FT 0.07%/0.06%, far-invisible FT 2.7%/2.1%,
   near-visible FT 1.3%/1.5%. It is the only head that suppresses both far
   controls while maintaining high recall.
8. **Synthetic-data caveat.** The near-invisible positives are generated by
   turning away from the target; the hard-state history is synthetic. The
   paired, goal-only, distance-only and hard/natural controls address the main
   shortcuts, but transfer to real closed-loop near-target loss is not yet
   proven. This is why the next step is a closed-loop smoke, not integration.

## 5. Decision and next step

**Offline gate verdict:**

- P1-2 / P1-3 **near-target-invisible diagnostic head: PASS**
  (precision 0.914/0.935 >= 0.50; far-visible FT 0.07%/0.06% <= 5%;
  recall 0.813/0.834; paired AUC 0.990/0.991; goal-only 0.495; distance-only
  paired 0.5; hard/natural far-inv 0.947/0.969 and 0.954/0.965).
- P1-2 / P1-3 **visibility head: PASS nominally** (precision 0.615/0.631;
  far-visible FT 0.43%/0.40%) but far-invisible FT 45.7%/43.6% makes it unsafe
  for recovery.
- P1-2 / P1-3 **localizability head: FAIL** (precision 0.314/0.365).
- P0 and P1-1: FAIL / borderline; current-only and one-frame history are not
  enough.

**Recommendation:** the offline evidence now supports **one small closed-loop
smoke**, not controller integration and not full training. Use the P1-2
near-target-invisible trigger (or, if only the two original probes are allowed,
the P1-2 visible trigger with the far-invisible caveat), and a
**forward-progress-preserving recovery action** — not the Stage-2f turn-only
scan. Suggested smoke design (future round):

- 36 Dev-Val episodes (12 per band), frozen M0@0.7 baseline and paired
  recovery episodes;
- trigger = P1-2 near-inv head at the train-selected threshold;
- recovery action: brief reorientation toward the last high-confidence side
  (≤2–3 steps) then resume forward; no long in-place scan;
- metrics: SR/OSR/SPL/nDTW, premature Stop, timeout, near-inv trigger
  precision/recall, far-visible false-trigger, paired W/L;
- stop rule: if SR/SPL/nDTW do not improve over M0, stop this line.

The near-target-invisible head remains a **diagnostic** label; the proposed
smoke is a mechanism test, not a deployment. Do not connect the probe to the
controller until the closed-loop smoke reproduces the offline trigger gains.

## 6. Limitations

- The near-target supplement is synthetic: matched turn-away sequences, not
  real M0 near-target loss states. The hard-state history is also synthetic.
- The near-invisible positives are 1,647 Train / 433 Dev Val; the CIs are
  episode-level but the positives are synthetic.
- The token probe does not see raw M0 closed-loop states; the Stage-2g scalar
  probe showed hand-crafted features fail, which motivated this supplement.
- Single seed; 5-fold episode OOF plus external Dev Val; no multi-seed
  replication.
- Near-visible localizable is 1,596/1,600 Train and 400/400 Dev Val; the
  near-localizable subset is essentially the near-visible subset.
- The visible head's far-invisible false-trigger remains high; the near-inv
  head is diagnostic-only and needs closed-loop validation.
- No MEC training, no checkpoint changes, Final Test 300 sealed.
- The recovery action and threshold are not integrated; no closed-loop result
  is claimed.

## Appendix A. Metric definitions

- AUROC/AUPRC: standard rank metrics; AUPRC is for the positive class.
- Brier/ECE: 10-bin expected calibration error.
- P@0.5/R@0.5/Spec@0.5: positive-class precision/recall and negative-class
  recall at 0.5.
- Trigger score: `p` for the near-target-invisible head; `1-p` for the
  visible/localizable heads (low probability = flag).
- `near-target-invisible precision among flags` = flagged near-invisible
  states / all flagged states.
- `near-target-invisible recall` = flagged near-invisible / all near-invisible.
- `far-visible false-trigger rate` = flagged far-visible / all far-visible.
- `far-invisible false-trigger rate` = flagged far-invisible / all far-invisible.
- `near-visible false-trigger rate` = flagged near-visible / all near-visible.
- Threshold selection: on Train OOF only. `recall_0.5` = highest threshold with
  recall >= 0.5; `f1_far_visible_5pct` = max near-inv F1 subject to far-visible
  FT <= 5%; `precision_far_visible_5pct` = max precision subject to the same.
- Episode CIs: bootstrap over episodes, not states (200 resamples).
- Paired AUC: near-visible vs near-invisible within the same episode/position/
  distance/action pair; 0.5 = chance, 1.0 = perfect ordering.
- Goal-only baseline: 768 goal-token mean/std features; observable.
- Distance-only diagnostic: true distance used only for offline analysis, not
  as a model input; paired AUC is 0.5 because both states in a pair have the
  same distance.

## Q2 D 的终止修正是否造成过大的末步反馈或信用分配问题？

- DQN：终止修正均值 0.0609，中位数 0.0298，最大 0.6414；终止转移占 Episode 回报均值 0.682；修正 / 非终止步绝对尺度 = 18.3；平均 T/H = 0.317。
- PPO：终止修正均值 0.1553，中位数 0.1393，最大 0.6414；终止转移占 Episode 回报均值 0.682；修正 / 非终止步绝对尺度 = 85.7；平均 T/H = 0.317。
- DQN 最终 MA100 E2E：D 87.77，B 85.30，方案一 89.28 ms；最佳 Dev E2E：D 83.34，B 73.01，方案一 87.26 ms。
- PPO 最终 MA100 E2E：D 69.44，B 73.64，方案一 80.05 ms；最佳 Dev E2E：D 61.01，B 58.51，方案一 65.99 ms。

终止修正的占比由 `1 - T/H` 决定：T 越短，末步占比越大。若 D 与方案一（100% 末步回报）表现接近，说明 D 的稠密基底没有显著改善信用分配；若 D 明显优于方案一，说明逐步反馈有帮助；若 D 的 Q/Value 诊断更差，则终止修正可能带来不稳定。结论以第 4 节数值为准。

## Q5 是否有充分证据扩到三个随机种子？

- DQN：最终 MA100 E2E 第一名 方案B，领先第二名 2.47 ms；该算法下最大 Dev 近 5 次标准差 3.36 ms；领先/噪声 = 0.73。
- DQN：最佳 Dev E2E 第一名 方案B，领先 10.33 ms。
- PPO：最终 MA100 E2E 第一名 方案D，领先第二名 4.20 ms；该算法下最大 Dev 近 5 次标准差 2.69 ms；领先/噪声 = 1.56。
- PPO：最佳 Dev E2E 第一名 方案B，领先 2.49 ms。

Stage-2n 六次 run 的末 5 次 Dev E2E 标准差均值为 1.26 ms（范围 0.89–1.67 ms），可作为 Dev 验证噪声的参照。

判据（预先声明）：只有当同一方案在 DQN 与 PPO 中都领先，且领先幅度明显大于 Dev 验证噪声、并且没有系统性 Q 漂移/价值异常时，才值得直接扩到 3 个随机种子；否则单种子证据不足，应先复跑最接近的 1–2 个方案或增加验证任务。

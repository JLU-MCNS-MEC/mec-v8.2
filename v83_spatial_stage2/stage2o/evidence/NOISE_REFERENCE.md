# Dev-60 验证噪声参照

数据来源：Stage-2n 六次正式 run 的 `validation_curves.csv`（同一条 Dev-60、
同一部署、同一 MEC）。对每个 run 取最后 5 次验证（Episode 3200–4000）的
Dev 平均 E2E：

| 算法 | Seed | 末 5 次标准差/ms | 末 5 次极差/ms | 最佳 Dev/ms |
|---|---:|---:|---:|---:|
| DQN | 0 | 1.37 | 4.08 | 75.76 |
| DQN | 1 | 0.98 | 2.66 | 80.11 |
| DQN | 2 | 1.63 | 4.12 | 78.53 |
| PPO | 0 | 1.04 | 3.24 | 62.63 |
| PPO | 1 | 1.67 | 4.37 | 58.70 |
| PPO | 2 | 0.89 | 2.39 | 58.39 |

- 标准差均值：**1.26 ms**
- 标准差范围：**0.89–1.67 ms**
- 极差范围：**2.39–4.37 ms**

因此 Stage-2o 中小于约 1–1.5 ms 的方案差异不应被解释为真实差异；
2–3 ms 的差异仍需多 seed 才能确认；只有明显大于 4 ms 且跨 DQN/PPO
一致的差异才值得优先扩 seed。

预注册的收敛判据是“最近三次 Dev E2E 极差 ≤ 最佳值的 1%”，
对约 50–80 ms 的 Dev E2E 而言约 0.5–0.8 ms，比上述验证噪声更严格。
